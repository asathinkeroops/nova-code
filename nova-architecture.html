Nova Coding Agent · Loop-Centric Architecture

Nova Coding Agent 架构

Nova 是一个深度面向 DeepSeek 调优的终端编码 agent。所有模块都附着在同一个 Agent Loop 之上，靠两种机制接进来——port（每个 agent 恰好一个实现：model / systemPrompt / tools / history / options / compactor / permission / logger / events）与 hook（0..N 个订阅者，只观察或轻改）。这张图展示每个模块在循环中的位置：它在哪个阶段介入、做什么、依赖谁。

// 两种扩展机制：port（每个 agent 恰好一个实现）+ hook（0..N 个订阅者）。
// port 就是它那条 hook 链的内建首节点 —— compactor.compact 排在 pre_compact 之前。
async function agentLoop(messages, ctx /* AgentContext：9 个 port */) {
  const system = await ctx.systemPrompt.system();  // 按 epoch() 冻结 = 前缀缓存的 byte 0
  while (true) {
    const next = await ctx.compactor?.compact(messages, req); // 只追加 <compacted> 边界
    assertAppendOnly(messages, next ?? messages);            // 截断/原地改 → throw
    messages = next ?? messages;
    await hooks.runBlocking("pre_request", { messages });

    const view = ctx.compactor?.view(messages) ?? messages;  // 纯投影，不写回
    const turn = await ctx.model.call({
      system, messages: view, tools: ctx.tools.list(),  // 每轮重取：MCP 连接 / plan mode 才生效
      ...ctx.options.turn(),                              // /think · /effort · /config（/model 走转发式 ModelClient）
    });
    messages = appendMessage(messages, turn.message);          // append-only

    const d = decide(turn.stopReason);
    if (d.kind === "return") break;                           // end_turn / stop_sequence
    if (d.kind === "error") throw new LoopTerminatedError(d); // refusal
    if (d.kind === "truncated" && noToolCalls(turn))         // max_tokens：可恢复
      { if (++cont > maxTokensContinuations) throw …; continue; }

    // tool_use —— 每个 tool_use 必产出一个配对 tool_result（throw / 权限拒绝亦然）
    const results = await Promise.all(
      toolUses(turn).map(use => ctx.tools.execute(use, tc))  // permission.check → pre_tool_use
    );
    messages = appendMessage(messages, { role: "user", content: results });

    await ctx.history.commit(messages);                       // 持久化边界
    await hooks.run("post_commit", { messages });          // 此时每条消息才终局
  }
}

Project Layout · pnpm Workspace

工程目录结构

pnpm monorepo：库代码在 packages/*（@nova/<name>），可执行入口在 apps/，CLI 二进制为 nova。八个包，刻意维持在八个 —— 一个 200 行的关注点归属于拥有该主题的包，不单独成包： 任务编排在 tools/，子 agent 与记忆/压缩都在 agent/，沙盒在 safety/，slash 命令的实现在 apps/cli（只有类型契约留在 base/prompt）。
