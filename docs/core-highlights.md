# 拆解一个 DeepSeek 原生的终端 AI Agent：三大能力，一套架构

> DeepSeek 协议级适配（省钱）、内核级命令沙箱（安全）、Markdown 声明式扩展（灵活）——这是一个把"省钱、安全、灵活"刻进设计里的开源终端 AI 编程工具。

市面上的 AI 编程工具大多优先适配 Claude，DeepSeek 只是"能用"。**Nova 反过来——它是为 DeepSeek 从头设计的。** 下面用三个最抓人的点，讲清它凭什么不一样。

## 一、为 DeepSeek 省钱：缓存自动命中

DeepSeek 的服务端缓存能省下大半的钱，但它有个苛刻前提：**请求前缀必须字节级稳定，一变就失效。**

Nova 为此把"消息历史只追加、绝不原地改"做成了全栈最硬的约束，连写盘都做成前缀感知——前缀不变就追加，缓存稳稳命中。它甚至**默认关掉激进的上下文压缩**，因为在 DeepSeek 上，压缩打断前缀的代价比省下的更高。这是刻意的取舍。

配套的还有：DeepSeek 报错的中文翻译 + 自动重试、状态栏实时余额、`/usage` 把花费按缓存读写拆开——**缓存到底帮你省了多少，肉眼可见。**

## 二、默认安全：操作系统级沙箱

所有 `bash` 和子进程命令，都跑在 **操作系统原生沙箱**里（macOS 用 Seatbelt，Linux 用 bubblewrap），文件写入被内核级锁死在工作区内。

关键是**零配置、零摩擦**：

- 启动即开启，不用写规则、不用学语法。
- 不支持的平台上静默降级，绝不打断你干活。
- `~/.npm`、`~/.pnpm` 等缓存默认放行，`npm install` 照跑；`.ssh/`、`.git/hooks` 等敏感路径一律拦截。

权限引擎在上层可配置、可弹窗确认，OS 沙箱在下层不可绕过兜底——**两层纵深防御，让 AI 放手干活也不至于乱写你的机器。**

## 三、随手扩展：一个 Markdown 文件就是一项能力

Nova 的扩展哲学只有一句话：**放一个带 frontmatter 的 `.md` 文件，它立刻变成运行时能力。** 不改源码、不重新编译、提交到 Git 就能团队共享。

比如，定义一个只读代码审查子代理，只要这样一个文件：

```markdown
---
name: reviewer
description: 只读代码审查，输出 file:line 格式的问题
tools: [read, grep, glob, lsp]
readOnly: true
---
你是只读代码审查子代理。逐文件审查 diff，按 file:line 格式报告问题……
```

同一套模式还能定义**斜杠命令、按需加载的技能（Skills）**；再加上兼容 Claude Code 的**生命周期 Hook** 和 **MCP 协议桥接**——所有外部能力，都走声明式、零代码的入口，并且共享同一道权限门。

## 为什么它能做到这些？

这三点不是堆出来的功能，而是长在一套干净架构上：**一个统一的 hook 扩展点**（加能力 = 挂个 hook，不动核心循环）、**严格单向的包依赖**（核心循环不碰任何模型 SDK 和界面，纯粹可复用）、以及**全链路的 schema 校验边界**。
