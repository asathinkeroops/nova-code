目标

core 定义 agent 是什么，agent 包决定装配出哪几种 agent

今天 @nova/core 是「标准 loop + 匿名钩子总线」，机制的所有权是模糊的： createAgent 把 checkPermission 和 compactor 这两个明摆着的单一实现 转手注册成钩子（agent.ts:199-209），再靠「先注册的先返回」假装成默认值； memory 经 buildSystemPrompt() 压成一个字符串就消失了，loop 完全不知道有记忆这回事； 模型视图切片藏在 CLI 的 ModelClient 装饰器里偷改传输层入参。

改造后是三件事：

  • 端口化 —— 每个核心机制在 core 有一个具名接口、一个固定的调用位置、一处不变量断言。
  • 抽象上提 —— turn 生命周期（runTurn/抢救/中断标记/持久化收尾）从 agent 搬进 core。
  • 单一入口 —— core 只暴露一个 createAgent(ctx: AgentContext)，所有具体实现由 AgentContext 带进来。

export interface AgentContext {
  /* 必填 —— 没有它们 agent 跑不起来 */
  model:        ModelClient;            // 传输层
  systemPrompt: SystemPromptProvider;   // 记忆 + 技能 + 提示词，带 epoch()

  options:      OptionsProvider;        // 每轮模型参数

}

SystemPromptProvider

它对应今天 agent.ts:352-362 内联的那一坨：buildSystemPrompt(workspace, memory, sessionId, skillsBlock, language) —— 行为规则正文 → 技能清单 → 四层记忆 → <memory-instructions> → 语言守卫 → <identity>/<system-info>/<session> 标签。

不做成一个 string 的三个理由：

  • epoch() 是前缀冻结校验的锚点 —— 传字符串就没地方挂「本会话内不许变」这条校验。
  • 必须晚绑定：memory 在 /clear、/resume 时重载，skillsBlock 在技能加载后才有。
  • 主 agent 拼六段、子代理是固定角色提示词 —— 让它们成为两个实现，而不是一个 if。

顺手修掉一个隐患：buildSystemPrompt 里的 today 是每轮现算的（日粒度）， 跨午夜的会话会静默失效一次前缀缓存，整段历史重新 prefill。epoch 锁死后就没了。

规则

让「传一次对象」安全的唯一条件

今天所有东西都藏在 getter 后面是有原因的 —— 这些东西会话中途会变：

变的东西触发端口里怎么表达
模型/modelmodel 传一个转发壳，稳定对象、活的行为
思考预算 · effort/think · /effortoptions.turn() 每轮调用
工具清单MCP 后连接 · plan modetools.list() 是方法
设置/configoptions.turn()
sessionId/resume · /clearsystemPrompt.epoch()
记忆只在会话边界systemPrompt.system()，且被 freezeSystemPrompt 锁住
写进 ports.ts 的文件头

容器本身是一次性构造的稳定对象；一切会变的东西藏在端口的方法背后，绝不做成字段读取。 违反这条的表现很隐蔽：不是崩溃，是 /model 切了不生效，或者功能一切正常但前缀缓存全失效。

流程

端口化之后的 agent loop

端口 单一实现 · 阻断钩子 首个非 undefined 生效 · 通知钩子 广播、吞异常 · 断言 core 校验

第 0 层 · turn 边界

runTurn(input)
  1. 【阻断】pre_user_prompt      → 改写 input，或否决整个 turn
  2. base = history.current() + userText(input)
  3. 【通知】post_messages         → TUI 立刻回显用户气泡
  4. ──────► agentLoop(...) ◄──────
  5. 收尾（成功 / 中断 / 抛错，三条路都走）:
       a. 抢救历史 pairingIsComplete(latest) ? latest : lastCommitted
       b. 中断 → 追加 <interrupted> → 【通知】post_messages
       c. 【端口】history.commit(final)
       d. recordInjections → EventSink
       e. 【通知】post_turn / error

第 1 层 · loop 入口（每 turn 一次）

system = await systemPrompt.system()
   └─ 【断言】freezeSystemPrompt：epoch() 未变 ⇒ 必须复用缓存值
             变了 ⇒ 告警（默认）/ 抛错（strict）

第 2 层 · 迭代

  1. 轮次兜底
    首次超限 → 追加「不要再调工具」提示并剥掉 tools；二次 → 抛错。
  2. 压缩 Compactor pre_compact append-only
    compactor.compact() 排在钩子链链首：返回新数组则短路，返回同一引用则钩子链继续跑。 无论结果出自端口还是钩子，都过 assertAppendOnly。变了 → post_messages + post_compact。
  3. 组装请求 pre_request
    可覆盖 system / messages / tools / maxTokens / thinkingBudget。messages 覆盖会回写 canonical 历史 —— 后台通知、monitor 通知、plan-mode 提醒都走这条。
  4. 视图切片 compactor.view() 新位置
    从 CLI 的 withCompactionSlice 装饰器移进 loop，位于 pre_request 之后、model.call 之前，不回写 canonical 历史。
  5. 模型调用 ModelClient post_request
    抛错也发 post_request{error} 再向上抛；成功则累加 usage。
  6. assistant 落地 post_assistant post_messages
    先追加去掉 tool_use 的内容 —— 渐进揭示第一步。
  7. 停止原因裁决 decide()
    error → 抛 LoopTerminatedError；return → 返回；pause_turn → 下一轮； truncated 且无工具调用 → 预算内追加「接着写」提示，耗尽则抛；无 tool_use → end_turn 返回。
  8. 工具 · 阶段一：逐个揭示 + 授权 PermissionGate pre_tool_use
    每个 tool_use 先揭示进 assistant 消息（卡片逐个亮起），再 pre_permission → permission.check()（链首，拒绝即短路）→ pre_tool_use 钩子链 → post_permission。 结束后把 assistant 恢复成模型原始块序。
  9. 工具 · 阶段二：并发执行 post_tool_use 配对
    受 toolConcurrency 限流；每个结果都可被 post_tool_use 整体替换；末尾兜底补齐任何缺失的 tool_result。
  10. 提交边界 history.commit() post_commit
    post_user_message → pre_continue 注入 → core 亲自调 history.commit() → 发 post_commit 给 transcript / TUI → 回到 ①。

兼容

钩子机制：16 个点一个不删

端口不是钩子的替代品，而是钩子链上永远排在最前面的那个内置节点 —— 这正是今天 createAgent 的做法（「Register first so user hooks registered later can override the defaults」）。 所以执行语义零变化，只是那个匿名闭包变成了具名、带类型、被 core 校验的节点。 

// 权限
permission.check(use, ctx)          ← 端口，链首
  ├─ 拒绝 → 短路，跳过后续钩子
  └─ 放行 → pre_tool_use 钩子链继续，任一返回 {allow:false} 即拒

// 压缩
compactor.compact(messages, ctx)    ← 端口，链首
  ├─ 返回新数组 → 短路
  └─ 返回同一引用 → pre_compact 钩子链继续
最终结果无论出自哪条路，都过 assertAppendOnly
类别点
阻断 6 个，不变 pre_user_prompt · pre_request · pre_tool_use · post_tool_use · pre_continue · pre_compact
通知 10 个，不变 post_assistant · post_request · pre_permission · post_permission · post_user_message · post_messages · post_commit · post_stop · post_compact · post_turn · error

现在挂在上面的东西全部不受影响：

  • transcript 写入器 —— 7 个点（改造后由 core 的 attachRecorder 推给 EventSink）
  • cli/hooks.ts 声明式 shell 钩子桥 —— 9 个点
  • cli/headless-events.ts —— 3 个点
  • cli/context.ts 注入器 —— pre_request×2、pre_continue×2、pre_user_prompt
  • subagent.ts 流式转发 —— post_assistant、post_tool_use
已核实

agent.on(...) 签名不变，所有 payload 形状不变，所有短路语义不变。CLI 侧零改动。

由此得到的三个结果：

  • subagent.ts 从「第二套 agent 实现」降级成一个工具 —— 341 行里真正跟 agent 构造有关的只有 212-257 那 45 行，改造后是一个配置对象。

需要说清楚的是：CLI 里的 goal-eval.ts、auto-classify.ts、predict.ts 和压缩用的 summarizer 不属于这一类 —— 它们是裸的 ModelClient.call() 单次调用，没有工具、没有多轮，套 agent 是过度抽象。保持现状。

代价

要认的三笔账

  • 推翻 CLAUDE.md 现有的两条契约。 「单一扩展点 HookRegistry，没有独立的 observer / compactor / permission 选项」要重写成端口清单 + 钩子职责； 「保持七个包」要放行第八个包 @nova/model。不改文档，下一个任务会拿旧规则来「修复」你。
  • core 不再是机制无关的通用 loop。 任何使用者都得理解 compaction / systemPrompt 这些概念，哪怕全传 no-op。这是这次改造要的方向，但账要认。
  • 覆盖语义收紧。 今天用户钩子靠「后注册 + first-non-undefined-wins」覆盖内置权限 / 压缩；端口化后覆盖只能是替换端口实现。 已核实 CLI 侧无人这么用，仅 agent.test.ts:314/535 两个用例在测这个语义 —— 而它们在「端口=链首」的设计下依然成立。

换来的是：三条最容易被后人破坏、且破坏后只表现为性能塌陷或数据静默不一致的不变量，从文档变成断言； 机制的实现从散落在 agent / cli / safety 三处，收拢成「core 编排 + 各包实现一个接口」。
